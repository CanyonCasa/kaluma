# Kaluma Fork — Fix Summary & Workflow

> **Unofficial personal fork.** This document describes a personal fork of
> [`kaluma-project/kaluma`](https://github.com/kaluma-project/kaluma), created to
> make a dormant upstream project usable again for personal Raspberry Pi Pico
> (RP2040) projects. The underlying code base is the work of the original Kaluma
> developers and contributors. The fixes and this document were **generated by an
> AI agent (OpenHands) on behalf of the repository owner**, then reviewed by the
> owner.
>
> **Caveat:** the C-language fixes below were reviewed against the exact
> pico-sdk version the project pins but have **not been compiled or tested on
> hardware**. Treat them as unverified until you build the firmware and confirm
> the behaviour on a Pico.

---

## 1. Context

[Kaluma](https://kalumajs.org/) is a tiny JavaScript runtime for the RP2040,
powered by JerryScript, with support for RP2 PIO (Programmable I/O) assembly
embedded in JavaScript. The upstream project is currently **dormant**, so several
open bug reports were left unfixed. This fork takes on the task of evaluating and
fixing the bugs that block the project from being usable again.

All 33 open issues in the upstream repository were triaged. Five of them were
actionable code-level bugs that were fixed. Two others (#687, #692) were analysed
but intentionally left as follow-ups (see §5).

### 2.1 #688 — `ASM.delay()` bounds checking

**Root cause.** `delay(val)` computed `c |= val << 8` with no validation. The
delay field shares the same 5-bit field (bits 8–12) with the sideset value:
sideset occupies the upper bits, delay the lower bits. An out-of-range `val`
bleeds into the sideset bits and corrupts the encoded instruction.

**Fix.** Added a `_maxDelay()` helper that computes the maximum valid delay for
the current sideset configuration (mirroring pico-sdk's
`pio_encode_delay` / `pio_encode_sideset` layout), and `delay()` now rejects:

- non-numeric values,
- fractional values (a hardware delay must be an integer number of cycles),
- negative values,
- values exceeding the delay bits left over after sideset.

### 2.2 #689 — `ASM` program size limit

**Root cause.** `ASM` had no cap on the number of instructions; a program longer
than 32 instructions would be truncated by the hardware.

**Fix.** Added a `check()` method that throws a `RangeError` once the program
exceeds 32 instructions (the RP2040 PIO capacity). Every one of the 9
instruction methods (`set`, `wait`, `in`, `out`, `push`, `pull`, `mov`, `irq`,
`nop`/delegating helpers) now ends in `return this.check();`, so an oversized
program fails fast at assembly time instead of failing obscurely on the board.

### 2.3 #690 + #691 — PIO state-machine teardown & instruction-memory clear

**Root cause.** Neither state machines nor the PIO instruction memory were ever
released or cleared between program runs. On the hardware this means:
- state machines created by one program kept running after it ended (#690), and
- the instruction memory was not reclaimable, so each subsequent `.load` was
  assigned a lower and lower offset until `pio_add_program` could not place the
  program (#691).

The code base already had a `km_pio_init()` (called only at boot) that cleared the
instruction memory and unclaimed state machines — but it was never re-run on
program end.

**Fix.** Added `km_pio_cleanup()` in `targets/rp2/src/system.c` that, for both PIO
instances (`pio0`, `pio1`):
- disables every state machine (`pio_sm_set_enabled(…, false)`),
- unclaims any claimed state machine (`pio_sm_unclaim`),
- clears the instruction memory (`pio_clear_instruction_memory`).

It is called at the start of `km_system_cleanup()`, which is the single path every
program-end routes through (`.load`, `.reset`, `CTRL+D` soft reset, and program
termination). Each newly loaded program therefore always starts from a clean PIO
state.

> **Not verified on hardware** — no ARM toolchain/cmake in the working
> environment. Every PIO API used is confirmed present with the correct signature
> in both the pinned pico-sdk and the 2.0.0 submodule, and they are the same calls
> the pre-existing `km_pio_init()` already uses.

### 2.4 #686 — `.help` de-duplication + `CTRL+Z` documentation

**Root cause.** `km_repl_register_command()` appended a new entry on every call,
and modules (e.g. the `fs` module) re-register their dot-commands on every program
run, producing many duplicate lines in `.help`. The `CTRL+Z` shortcut (exit shell)
was also missing.

**Fix.**
- `km_repl_register_command()` is now **idempotent**: if a command with the same
  name is already registered, the re-registration is skipped.
- Added a `CTRL+Z  Exit shell (kaluma --shell)` line to the `.help` output,
  matching the kaluma CLI shell behaviour.

> **Not verified on hardware.**

## 3. Testing

- `tests/rp2.test.js` — a Node-based unit test that loads the **real**
  `src/modules/rp2/rp2.js` with a stubbed `process.binding` (no hardware or
  firmware build required). It covers the `delay()` bounds rules (including
  sideset-dependent limits and optional-sideset cases) and the program-size limit.
  **Result: 9 passed, 0 failed.**
- `node --check` passed on both modified/new JS files.
- The C fixes could not be compiled in the working environment (no
  `arm-none-eabi-gcc` / `cmake`), so they are verified by review against the pinned
  SDK, not by a build.

To run the JS tests:

```bash
node tests/rp2.test.js
```

## 4. Workflow

1. **Located & cloned** the repository (`kaluma-project/kaluma`, branch `master`).
2. **Triaged** all 33 open issues and confirmed the root cause of each actionable
   bug by reading the relevant source and the pinned pico-sdk headers.
3. **Implemented** the fixes (#688, #689 in JS; #690, #691, #686 in C).
4. **Tested** the JS layer under Node (9/9 passing) and syntax-checked all JS.
5. **Verified** each PIO API used exists with the correct signature in both
   supported pico-sdk versions.
6. **Committed** on branch `fix/pio-and-repl-issues` as logical commits (JS fixes
   + tests, PIO teardown, REPL `.help`), then added `docs:` commits for the README
   notice and this summary.
7. **Published** to a personal public repository with both the `master` (base) and
   `fix/pio-and-repl-issues` branches, so the changes are visible as a diff.

### Commits (on `fix/pio-and-repl-issues`)

```
docs:  add unofficial-fork notice, fix list, and AI-generated attribution   (README)
docs:  add fix summary & workflow (docs/fix-summary.md)
repl:  de-duplicate registered commands and document CTRL+Z                  (#686)
rp2:   stop PIO state machines and clear instruction memory on program end   (#690, #691)
rp2:   bounds-check ASM delay() and enforce PIO program size limit           (#688, #689)
```
